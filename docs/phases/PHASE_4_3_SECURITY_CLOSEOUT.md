# XUSHU Phase 4.3 安全可靠性收尾与提交前审计

日期为 2026-11-12（Asia/Shanghai）。工作区为 `D:\MyProject\xushu`，分支 `main`，基线为 `f3ff6a8`。本轮复核 Phase 4 的两个安全可靠性问题，界面源码未改动。

## 1. 根因与修复前证据

修复前在 D 盘隔离 Git 仓库、独立 SQLite 及测试设置中执行 `cargo test -p xushu-core --test claude --locked closeout_ -- --nocapture`。退出 **101**，五个断言全部失败。

| 风险 | 根因 | 修复前观察 |
| --- | --- | --- |
| Spool 持续被占用 | 停用和卸载先调用 `drain_pending`。导入器将 Windows 独占写句柄视为待重试，排空条件一直无法满足。 | 停用返回“仍有未导入的 Hook 事件”，原配置保持启用。 |
| 导入异常 | 导入失败直接经 `?` 退出撤销流程，移除配置尚未开始。 | 隔离库触发器拒绝事件插入，卸载返回 SQLite 约束错误 1811。 |
| SQLite 写锁 | 停用依赖导入状态写入。旧补偿策略还会在数据库写入失败时恢复 Hooks。 | 第二个连接持有真实写事务，停用报错后仍有 **6** 个受管 Hooks，预期为 **0**。 |
| 项目根目录 Junction | 设置读取直接使用重新解析后的项目路径，重解析点检查只覆盖 `.claude` 和设置文件。 | 旧预览被拒绝。根路径被替换后，重新预览仍未阻止接入。 |
| 同路径目录替换 | 旧预览只绑定解析路径、配置字节和计划条目，缺少文件系统身份。 | 更换为路径相同的空目录后，旧预览仍被安装入口接受。 |

## 2. 停用、卸载与导入

- 停用和卸载先锁定项目设置操作，结构化移除本项目的受管条目，再回读配置。只有确认设置中已无受管条目才更新 SQLite。保留第三方 Hooks、权限、其他配置及已入库历史。
- 若 SQLite 更新被写锁或触发器拒绝，配置保持关闭。IPC 返回明确的部分成功错误，查询可见“项目中已无 XUSHU Hooks，数据库仍记录启用”。故障解除后重试停用或卸载，补齐本地记录。配置移除或回读未确认时，操作返回错误，状态不会报告为已停用。
- 事件消费独立运行。导入时核对当前项目设置、项目根指纹与采集代次，写入事务内再核对启用状态和代次。撤销后不消费积压为新活动。可读的旧代次信封在后续导入时被忽略并清理，仍被占用的文件等待下次刷新。旧接收进程迟到投递也按旧代次处理。已在撤销前提交的事件留在历史中。
- 迁移 5 新增采集代次和项目根目录身份。首次启用与撤销后重新启用生成新的代次，重复安装同一有效配置保持原代次。已启用的旧版配置和不带代次的信封按代次 0 兼容。接收器或收件箱不可用时，仍可在配置路径和备份可用的情况下撤销采集。
- 安装或修复的数据库写入失败时，仅在当前设置仍为本次写入的文件和字节时恢复原配置。外部编辑触发冲突并保留新内容。SQLite 写入仍可能等待既有的忙超时，复测使用 WAL 下的独立写连接。[SQLite WAL](https://www.sqlite.org/wal.html)

## 3. 授权路径与写入边界

- 分别保留已登记项目路径及实际解析路径，按路径组件判断是否一致。逐级检查项目根、关键父目录和应用备份目录，拒绝链接、Junction 和重解析点。已有接入记录若保存了根目录身份，实际身份变化时，预览、安装、修复、停用和卸载均拒绝继续。
- Windows 用卷序列号和 128 位文件 ID 识别目录和文件。预览绑定项目根、设置目录、设置文件身份与字节。安装和修复实际写入前重新检查。已校验目录在操作期间持有不共享删除的句柄，实测可阻止祖先目录在持有期间被重命名。[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) · [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info)
- 同一项目的 XUSHU 设置操作使用文件锁串行化。项目设置和备份都经过路径检查。应用在已校验的设置目录写入新的临时文件，替换前再次比较目标身份和原始字节。安装失败的补偿沿用同一校验，备份保留原设置的私有内容。

## 5. 未解决的技术边界

- SQLite 与项目文件之间没有跨资源原子提交。若应用在文件替换后、数据库提交前被终止，物理配置与数据库记录可能暂时不同。撤销路径保留关闭结果并允许重试，导入会核对现有设置和代次。
- Windows 目录句柄缩小了路径替换窗口。外部编辑器仍可在最终校验与叶文件替换之间并发操作。身份和字节比较可拒绝已观察到的变化。无法读取身份、目录被替换、备份失败或替换不受文件系统支持时，写入返回错误。网络盘、macOS 和 Linux 的具体文件系统行为 **NOT_RUN**。
- 旧的接入记录在迁移后可能没有根目录身份。登记路径及父目录仍须通过重解析点校验，用户下一次授权安装或修复时补记身份。旧记录无法证明迁移之前是否发生过普通目录原位替换。
- 新代次参数由本轮配套接收器验证。旧接收器二进制与新配置混用、当前构建的用户手动 Claude Code 会话、生产安装包 sidecar、升级路径和真实 Hook 超时 **NOT_RUN**。已有开发构建 E2E 与历史真实会话证据各自保留。
