# ADR-0008：项目记忆、开发决策与跨会话恢复

- 状态：已采纳（Phase 5，2026-11-12）
- 关联：ADR-0002（SQLite 持久化与 IPC）、ADR-0004（独立验收引擎）、ADR-0007（Claude Code Hooks）
- 迁移：`crates/xushu-core/migrations/0006_project_memory_and_recovery.sql`

## 1. 背景

Phase 5 需要补齐“事实 → 决策 → 记忆 → 恢复上下文”的长期链路。关键约束：

- 任务完成仍只由当前有效的独立验证证据与人工确认决定；记忆、决策、Hook 事件和 AI 文本都不能替代门禁。
- 恢复包必须来自真实数据库、只读 Git 与验收结果，不能为了提高“完整度”而编造 AI 总结。
- 项目数据必须严格隔离；默认不上传、不读取其他项目的私有文件。
- 旧数据库必须可迁移，迁移失败必须回滚，历史决策不能被静默覆盖。

## 2. 决策

### 2.1 长期记忆采用“类别 + 来源 + 确认状态 + 有效性 + 修订历史”

`project_memories` 保存当前版本，`project_memory_revisions` 保存每次变更快照。字段语义：

- `category`：项目目标、开发约束、技术架构决策、开发规范、已确认事实、风险、后续待处理、项目知识。
- `source_type`：user / system / git / verification / hook / inference。来源是标签，不是可信度本身。
- `confirmation_status`：unconfirmed / confirmed；`confirmed_at` 与状态由数据库 CHECK 约束保持一致。
- `validity_status`：active / archived；归档不删除历史。
- `linked_task_id` / `linked_evidence_id`：可选关联；读取与写入都校验同项目归属。

AI 推断（`inference`）默认只能创建为未确认，且禁止直接以 `confirmed: true` 创建。用户创建的记忆默认为已确认，因为内容由用户本人录入。

### 2.2 开发决策是追加式日志，已确认决策不可原地改写

`decisions` 保存当前状态，`decision_revisions` 保存每次变更。状态机：

```text
draft ──确认──> confirmed ──新决策确认──> superseded
  │                │
  └──废弃──> deprecated <──废弃──┘
```

- 草稿可编辑；已确认决策不可直接编辑。
- 需要变化时创建新决策，并可在草稿阶段选择 `supersedes_id`。
- 新决策确认时，在同一事务内把旧决策标记为 `superseded`，写 `superseded_by_id`；旧决策保留 `confirmed_at` 与全部修订历史。
- 旧决策必须处于 `confirmed` 才能被取代；已被取代/废弃的决策不能再被确认或再次取代。
- 决策可以关联任务，但任何决策操作都不修改 `tasks`、验收条件、证据或完成门禁。

### 2.3 恢复包确定性生成，不依赖 AI

恢复包从以下来源构建：

1. 项目身份、任务状态、阻塞原因、完成门禁 blockers（数据库）。
2. 当前 Git 分支、HEAD、dirty 与工作区代码指纹（只读 Git；失败显示 UNKNOWN）。
3. 独立验证运行、结果、证据 ID、过期原因（数据库，按生成时任务修订与代码状态重新计算）。
4. 已导入的 Claude Code 元数据（仅会话伪名、事件时间、工具状态；不含原始 Prompt/命令/输出/transcript）。
5. 已确认且有效的项目记忆；未确认记忆单独展示且明确“不是事实”。
6. 已确认决策；已被取代/废弃决策作为提示；草稿不进入恢复包。
7. 用户指定的下一步任务；未指定时只给出有依据的系统建议并标记“需人工确认”。

恢复包 Markdown 由确定性模板生成；不配置 AI Provider 也能使用。未来若增加 AI 摘要，只能作为可选增强，不能成为基础功能硬依赖。

### 2.4 快照保存指纹，过期状态通过“重新构建当前包并比较指纹”判定

`recovery_snapshots` 保存生成时间、指纹、Markdown、结构化包 JSON 与计数。指纹覆盖：

- 项目更新时间/归档状态；
- Git 分支、HEAD、dirty、detached、unborn、工作区代码指纹；
- 任务状态、修订、阻塞原因；
- 记忆修订/确认状态/有效性；
- 决策状态/修订；
- 验证运行 ID/结果/执行状态；
- Claude 最近事件与会话结束确认；
- 下一步任务与建议读取文件。

`get_recovery_overview` 会重新构建当前包，与最近快照指纹比较，返回 fresh / stale / no_snapshot。历史快照在 UI 中明确标记为历史；复制历史或过期快照时，剪贴板文本开头加入警告。

### 2.5 数据来源优先级与冲突呈现

恢复包开头与 UI 明确声明：

- 真实任务状态、验收证据与 Git 状态优先于记忆/决策文本。
- 记忆与决策是开发上下文，不是事实替代品。
- 结构化冲突（例如“任务已完成但证据已过期”）进入 `conflicts`；缺失信息进入 `missing_information`。
- 不进行自由文本语义冲突的自动判定；不假装系统能理解任意自然语言记忆与真实状态的关系。

### 2.6 安全与容量边界

- 所有记忆/决策/快照 IPC 都要求项目 ID；读取与写入校验项目归属，跨项目返回 `NOT_FOUND` 或 `VALIDATION_ERROR`。
- 前端不获得通用 SQL、文件系统写入或 shell 能力；业务校验仍在 Rust。
- 恢复包只检查白名单协作文件是否存在，不读取项目文件内容。
- 不读取 Claude Code transcript、Prompt、工具输入输出或密钥。
- 长文本在恢复包中最多保留 4000 字符；记忆/决策原始数据仍在 XUSHU 中可查看。
- 快照 Markdown 上限 4 MiB、结构化包上限 8 MiB；每个项目保留最近 20 份快照。
- 恢复包包含本地路径与用户记忆，预览与复制均由用户主动触发；不会自动注入 Claude Code 会话。

## 3. 后果

### 3.1 收益

- 恢复上下文可以逐项追溯到数据库、Git 或验证运行，不依赖模型“记忆”。
- 决策历史不可丢失；被取代关系双向可查。
- 快照过期是可见状态，不会把旧结果冒充当前事实。
- 迁移 6 为纯追加表，不修改既有业务表；旧数据保留。

### 3.2 代价

- `get_recovery_overview` 需要重新构建当前包，任务/记忆较多时比普通查询更重；恢复页不是高频页面，可接受。
- 已确认决策不可原地修改，用户必须通过“创建取代决策”或“废弃”表达变化；这是有意的摩擦。
- 恢复包是摘要，长文本会截断；完整内容需回到项目上下文。
- 不做自由文本语义冲突检测，只能呈现结构化冲突与来源优先级。

## 4. 被否决的方案

- **把 AI 摘要作为恢复包核心**：不可验证，且违反“无 AI 也不能失去基础能力”。
- **允许编辑已确认决策并覆盖原文**：会破坏历史可信度；改用取代/废弃。
- **只保存最新恢复包，不保存历史快照**：无法区分当前与历史，也无法追溯旧上下文。
- **把 Hook 事件或记忆当成完成证据**：违反 Phase 3 完成门禁。
- **为恢复包扫描整个项目目录**：隐私边界过大；只检查白名单文件是否存在。

## 5. 回滚与兼容

- 迁移 6 只新增表与索引，不修改 1–5 迁移。
- 回滚应用版本时，旧版本会因 schema 版本高于支持版本而拒绝打开，避免静默降级；数据库与 WAL 保留，可回到当前版本。
- 删除 UI/命令不会删除已存数据；记忆、决策与快照表可保留供后续版本读取。
- 若未来改变恢复算法，应新增 ADR 与指纹版本前缀，不应静默改变旧快照含义。

## 6. 验证

- Rust：`tests/memory.rs`、`tests/decisions.rs`、`tests/recovery.rs`、`tests/persistence.rs` 覆盖隔离、事务回滚、迁移保留、重启、过期与快照保留。
- 前端：Vitest 覆盖知识页、恢复摘要、剪贴板文本、过期确认与历史快照。
- 桌面：隔离数据目录的 Tauri/WebView2 E2E 验证 fresh → stale → fresh、任务状态不变、页面可见与正常数据库不变。
